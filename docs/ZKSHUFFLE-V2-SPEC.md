# zkShuffle v2 — mental poker для ShinyPoker (технический план)

**Цель:** карты игрока не видит НИКТО, кроме него самого — ни дилер-бот, ни хост,
ни валидаторы. v1 (commit-reveal) доказывает, что раздачу нельзя подтасовать, но
бот выводит колоду, чтобы раздать карманные карты → он их технически «знает».
v2 убирает это доверие целиком.

Сайт сегодня честно описывает v1 (см. provably-fair §4). Это НЕ переписывается
на «zkShuffle» до того, как всё ниже реально работает и проверено — крипто-
сообщество открывает контракт первым делом.

---

## 1. Протокол: Barnett–Smart mental poker (дискретный логарифм, без trusted setup)

Классическая схема (Barnett & Smart, 2003; современная реализация — arkworks
`mental-poker` от Geometry Research):

1. **DKG за столом.** Каждый из k игроков генерирует пару (sk_i, pk_i) в браузере;
   агрегированный ключ стола pk = Σ pk_i (с proof of knowledge на каждый вклад,
   чтобы отсечь rogue-key).
2. **Кодирование колоды.** 52 фиксированные точки кривой (BN254/alt_bn128 — на
   EVM есть precompiles ecAdd/ecMul/pairing) — публичный маппинг карта↔точка.
3. **Коллективное перемешивание.** Каждый игрок по очереди: берёт вектор из 52
   ElGamal-шифротекстов, применяет свою случайную перестановку + ре-рандомизацию
   и публикует **shuffle argument** — доказательство корректности перемешивания,
   не раскрывающее перестановку. Варианты:
   - **Bayer–Groth shuffle argument** — верифицируется на EVM напрямую, но для
     52 карт это миллионы газа за игрока (на Somnia дёшево в STT — нужен бенч);
   - **Groth16-обёртка (рекомендация)**: circom-схема «shuffle+remask корректен»,
     на контракте одна pairing-проверка (~300k газа). Это и есть подход
     zkShuffle (Manta/Geometry). Есть готовые схемы — вендорить и ревьюить, не
     писать заново.
4. **Раздача карманных.** Для карты, идущей игроку i: все ОСТАЛЬНЫЕ публикуют
   свои decryption shares с Chaum–Pedersen proof (равенство дискретных логов).
   Игрок i снимает последний слой локально — карту видит только он.
5. **Борд.** Все публикуют shares → карта расшифровывается публично.
6. **Шоудаун.** Раскрытие карманных = игрок публикует свой share (+proof).

Свойства: приватность против k−1 сговорившихся; никакого trusted setup (для
Bayer–Groth) или один универсальный (Groth16 — powers-of-tau).

## 2. Роль дилер-бота в v2

Бот перестаёт видеть карты и становится **координатором**: собирает/релеит
транзакции этапов, следит за таймаутами, наказывает зависших. Опционально бот —
(k+1)-й «участник» перемешивания, чтобы даже полный сговор игроков без бота не
восстанавливал колоду.

## 3. Liveness — главная инженерная боль

Любой этап может «зависнуть» (игрок закрыл вкладку):
- DKG/shuffle не завершён → руки нет: таймаут → отмена, виновному — таймаут-штраф
  (как текущий kickIdle);
- Игрок не публикует share на борд/шоудаун → его рука мертва (fold + штраф),
  борд достраивается без его share? НЕТ — share нужен от всех ⇒ протокол
  требует threshold-декрипцию (t-of-k, Shamir поверх DKG) — закладывать сразу,
  иначе один ливер убивает руку. Это усложнение №1.

## 4.契约ная часть (интерфейс уже готов под свап)

`PokerRoom` знает дилера через `IPokerDealer` — v2 = новый контракт, room не трогаем:

```solidity
interface IZkDealerV2 {
    function openHand(uint256 tableId, uint8[] calldata seats, uint256[2][] calldata pubkeys) external returns (uint256 dealId);
    function submitShuffle(uint256 dealId, bytes calldata ciphertexts, bytes calldata proof) external; // по очереди мест
    function submitHoleShare(uint256 dealId, uint8 forSeat, uint8 cardIdx, bytes calldata share, bytes calldata cpProof) external;
    function submitBoardShare(uint256 dealId, uint8 cardIdx, bytes calldata share, bytes calldata cpProof) external;
    function timeoutStage(uint256 dealId) external; // отмена/штраф зависшего этапа
}
```

Верификация: groth16 verifier (авто-генерённый snarkjs) + Chaum–Pedersen на
precompiles. Хранение: 52 шифротекста × k этапов — на Somnia ок, но писать
только последнюю версию колоды + хэш-цепочку промежуточных.

## 5. Клиент

- Крипто в браузере: WASM-сборка arkworks `mental-poker` ИЛИ snarkjs+circom
  артефакты (proving key для shuffle-схемы ~десятки МБ — грузить лениво, кешировать).
- Время пруфа перемешивания на ноуте: секунды–десятки секунд (бенчить!). Для
  UX: шаффл идёт «под» анимацию раздачи; на мобилках может не тянуть → фолбэк
  v1-стол.
- Столы v2 помечаются в лобби; v1 и v2 живут параллельно (rooms обоих типов).

## 6. Этапы и честная оценка

| Этап | Что | Оценка |
|---|---|---|
| R0 | Вендоринг и ревью готовых схем (geometry mental-poker, manta zkShuffle), бенч пруфов в браузере и газа верификации на Somnia | 2–4 дня |
| R1 | Оффчейн-прототип на двоих: DKG→shuffle→deal→showdown в двух вкладках, без контракта | 3–5 дней |
| R2 | Контракт IZkDealerV2 + verifier'ы + таймауты + threshold-декрипция | 1.5–2 недели |
| R3 | Интеграция в стол (UI этапов, фолбэки), нагрузочные и adversarial-тесты | ~1 неделя |
| R4 | **Внешний аудит криптографии** — не опционально: одна ошибка в proof-веrifier = все банки столов | внешний, недели |

Итого до продакшена с деньгами: **~4–6 недель календарно**, из них львиная доля —
не «написать», а **проверить**. Написанный за день верифаер, который никто не
ломал, — это не zk-покер, а лотерея на новом уровне.

## 7. Чего не делаем никогда

- Не выкатываем «shuffle без пруфов» под именем zkShuffle.
- Не пишем свои крипто-примитивы, где есть аудированные реализации.
- Не убираем честный §4 с provably-fair, пока v2 не заменил v1 на столе.
